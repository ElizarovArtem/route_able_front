# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
npm run dev          # start Vite dev server on port 3000
npm run build        # vite build + tsc (use when changing routes/config)
npm run type-check   # TypeScript check without bundling
npm run test         # Vitest run once
npm run test -- --watch  # Vitest watch mode
npm run server       # json-server from db.json on port 3005 (local mock API)
```

Before handing off changes: run `npm run type-check` and relevant tests. Run `npm run build` when changing routes, app setup, shared config, or production behavior.

## Environment

Create `.env` with:
```
VITE_API_URL=http://localhost:3005
VITE_NODE_ENV=development
```

Add new env vars through `src/f.shared/config/env.ts` (not raw `import.meta.env.*`). Document new `VITE_*` vars in `README.md`.

## Architecture: Feature-Sliced Design

Source is split into ordered layers under `src/`. Imports must flow **downward only**:

```
a.app → b.pages → c.widgets → d.features → e.entities → f.shared
```

| Layer | Purpose |
|---|---|
| `a.app` | Entrypoint, TanStack Router route files, root providers, global Zustand store, global SCSS |
| `b.pages` | Thin route-level screen compositions — assemble widgets/features/entities, own no reusable logic |
| `c.widgets` | Large reusable page blocks (chat panels, calendars, AI assistant, etc.) |
| `d.features` | User actions and mutations ("what can the user do?") |
| `e.entities` | Domain objects and read APIs ("what is this?") |
| `f.shared` | API clients, config, generic helpers/hooks, UI primitives, icons |

Never import upward or sideways between unrelated slices. If two slices share a helper, move it down to the lowest layer both can depend on.

## Slice Structure

Each domain segment in `d.features` and `e.entities` follows:
```
<segment>/
  api/
    queries/    ← React Query hooks
    requests/   ← Axios request functions
  model/        ← types, resolvers, stores, schemas, helpers
  ui/
  index.ts      ← public exports
```

Import from a slice's `index.ts` at the boundary. Deep imports are acceptable only when the existing code in that slice already uses direct paths.

## Routing

Routes live in `src/a.app/routes`. **Do not manually edit** `src/a.app/entrypoint/routeTree.gen.ts` — it is generated by TanStack Router. The root route (`__root.tsx`) owns global providers, layout, auth/subscription guards, and devtools. Keep route files thin; delegate screen assembly to `b.pages`.

## State & Data

- **Server state**: TanStack Query hooks in the owning slice `api/queries`, calling functions from `api/requests`.
- **Global client state**: Zustand slices composed in `src/a.app/store/store.ts`.
- **Local UI state**: plain React state for modal visibility, tabs, form-only state.

## API & Realtime

- HTTP: use `api` from `src/f.shared/api/client.ts` (handles auth refresh and error interceptors, sends credentials).
- Sockets: use `connectSocket`/`getSocket`/`disconnectSocket` from `src/f.shared/api/socket.ts`; never create socket clients inside UI components.
- Uploaded media URLs are built as `${VITE_API_URL}/uploads/<file>`.

## Styling

- SCSS modules beside components (`*.module.scss`).
- Global styles and variables in `src/a.app/styles`.
- Prefer shared UI primitives from `src/f.shared/ui` for app-specific controls; use Ant Design where already established or for complex built-in behavior.
- Use `@/` import alias (configured in `tsconfig.json`).

## Key Dependencies

- **TanStack Router** — file-based routing
- **TanStack Query** — server state
- **Zustand** — global client state
- **Ant Design** — UI component library
- **LiveKit** (`@livekit/components-react`) — video lessons
- **TensorFlow MoveNet** (`@tensorflow-models/pose-detection`) — AI workout pose detection; model served from `/models/movenet/singlepose/lightning/model.json`
- **Socket.IO client** — realtime chat
- **Zod + React Hook Form** — form validation

## Tests

Vitest + Testing Library. Place tests beside what they cover, named `*.test.ts` / `*.test.tsx`. Prioritize routing guards, React Query hooks, form resolvers, and touched business logic. If a slice has no test harness, call that out rather than skipping coverage silently.
